# ADR-001：先实现本地元数据缓存，共享种子库延期

状态：本地缓存已实现；共享种子库按本次范围延期，后续独立评估。
日期：2026-11-06

## 背景与决定

已有检索依赖微信读书和豆瓣，相同关键词、ISBN、详情查询会重复请求。先在数据源函数边界增加解析后的本地缓存，覆盖所有调用方。使用插件目录 `metadata-cache.json`，避免与 settings/activity 的频繁保存互相覆盖。缓存有格式版本、7 天 TTL、200 条容量，键包含操作、来源、关键词或规范化 ISBN，作者匹配也单独纳入键。相同进行中请求共享 Promise，返回副本避免调用方补全元数据污染缓存。

不缓存错误、空列表和 null，允许恢复后重试。损坏或不可读缓存忽略，无法写入时仍返回在线结果；过期时重新查询，失败沿用现有界面错误行为，不静默回退陈旧结果。可通过命令清空缓存。文件随插件目录保存，若用户同步该目录，缓存也可能被同步；不承诺设备间一致性。

## 共享种子库候选设计

后续可以提供只读、用户主动启用的种子包。条目以来源 ID 为主键，ISBN 作为可多值的辅助索引；保留来源 URL、取得时间、格式版本、字段来源和授权信息。查询顺序拟为本地有效缓存 → 本地已导入种子包 → 在线源；需要明确过期、字段合并和用户覆盖优先级。

包使用清单版本、校验摘要、大小上限和原子替换；校验失败保留旧包。更新通过受信任的静态 HTTPS 发布入口提供，无自动上传用户查询、笔记或阅读记录。不同书籍版本不可仅凭书名合并；共享简介、封面等内容前必须确定许可与再分发条件。

## 延期理由与取舍

共享库还需要数据许可、版本身份、维护负责人、分发与更新、损坏回退、包体和隐私决策，当前仓库没有这些基础设施。本地缓存可以独立降低重复请求，因此建议共享部分不阻塞 0.5.0；后续单独验证中文书籍命中收益后再建设。只做内存缓存无法跨重载复用；把缓存混进设置会放大活动保存开销，均未采用。
